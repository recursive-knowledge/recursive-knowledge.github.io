Don’t improve the agent — improve the knowledge it leaves behind

Every self-improving system has to answer one question: as it gains experience from solving tasks, what should persist and improve over time? An agent fails a task, and there are many ways to improve it: tune its prompt (GEPA, OpenEvolve), rewrite the harness around it (Meta-Harness), let it distill its own successful runs into a skill library (Voyager, SkillWeaver), let it rewrite its own code (DGM), or even rewrite the procedure it uses to rewrite itself (HyperAgents).

Each of them answers the question the same way, if only implicitly: the agent is what should persist and carry the improvement. That answer is costly. One persistent agent must absorb every lesson it ever learns, and those lessons are often task-specific, redundant, or contradictory. Conflicting updates dilute useful behavior, and each new adaptation risks breaking what already worked.

We give the opposite answer. The agent stays generic, stateless, and disposable, so no update can break what already worked; improvement accumulates in what the agents write down. Because the lessons live in text rather than in the agent, they can be vetted: claims compete in a forum, contradictions are kept and scoped rather than averaged away, and only what recurs across tasks survives distillation.

Holding the solver fixed turns a design preference into a measurement. If a generic agent with a good knowledge base beats a purpose-built self-improving system, then agent machinery was never the scarce resource — knowledge was.

The bottleneck may not be the agent’s architecture. It may be the quality and structure of the information the agent can access and refine over time.

That is the claim this work makes, and the rest of the page tests it.

Agents discuss; the knowledge improves

Curation runs in three stages (the same three the animation below steps through) that climb a ladder of abstraction, from evidence about one task to guidance any later agent can use. Each task has its own thread, the task-level forum, where agents post what they found, quote earlier posts by id, and reply to one another — agreeing, disagreeing, or refining. In the cross-task forum, agents then compare findings across tasks and ask which claims survive beyond the task that produced them. A final distillation pass decides what later agents inherit. It is a selection step, not a summary: the distiller keeps claims that are actionable, evidence-grounded, and scoped, and drops advice that does not name the condition under which it applies.

The agents themselves carry nothing between tasks. Every agent is a fresh, stateless solver whose lifecycle is the loop’s first two steps: it seeds from the shared knowledge base, attempts one task, and hands its evidence to the forums. Solved tasks leave the pool, so the budget goes only to what is still open. Nothing in the protocol requires synchronized rounds (the agents could run asynchronously), but we batch them into generations because that makes progress easy to measure and directly comparable with the agent-centric baselines.

Stage 1

Task-level forum

Agents turn raw traces into local evidence (what helped, what misled) scoped to the task it came from.

Stage 2

Cross-task forum

Agents discuss what transfers across tasks. Each claim is grounded in a primitive; replies agree, disagree, refine, or synthesize. Disagreement counts as evidence, not noise.

Stage 3

Distillation

Surviving claims are distilled into typed bundles and written back to the base; later agents seed from them.

Why disagreement makes the knowledge better

  1. The claim After failing ARC-AGI-1 task b548a754, an agent posts a blanket conclusion: marker cells don’t control the grid’s geometry.
  2. The pushback A peer disagrees, citing a task solved in the same generation where the marker’s position determined the movement direction.
  3. What distillation keeps Both sides. The failure is narrowed to the one parameterization that actually failed, and the untried marker hypotheses are recorded as open leads.
  4. The payoff In the next generation, a fresh agent solves the task — with a rule from exactly the family the disagreement kept alive.

The protocol makes conflict explicit and makes it carry evidence; it does not manufacture it.

Inside the knowledge base

The knowledge base is a plain-text artifact: a set of typed claims — reusable strategies, falsified hypotheses, scoped pitfalls — each carrying the evidence that produced it. What makes an entry good is what it does to the next agent’s attempt: it is concrete enough to act on, names the conditions under which it applies, and gets revised or retired as new evidence arrives rather than duplicated.

Results

The evaluation spans five benchmarks: coding (Polyglot, SWE-bench Pro), abstract reasoning (ARC-AGI-1, ARC-AGI-2), and terminal skills (Terminal-Bench 2). Each run improves for 10 generations over a fixed task pool, and our numbers are means over three seeds. Every number is reproducible with the open-source KSI framework; see the benchmarks guide for datasets and run presets.

Finding 3The knowledge base transfers to new tasks and to new models

The final question is whether the knowledge base carries standalone value: whether the artifact, separated from the procedure that produced it, still helps on unseen tasks. The donor is the LLM whose run produced the frozen bundle; the recipient is the LLM that consumes it on held-out tasks, zero-shot: no new forum discussion, no recipient-side distillation, only a task-conditioned adapter that turns the bundle into a short memo for the task at hand.

The shift to externalized intelligence

As self-improving agent systems have emerged, the default playbook has been to build increasingly complex machinery: specialized prompts, dynamic harnesses, recursive self-modification loops. Our results show much of that machinery is substitutable — a generic, stateless agent with curated, evidence-grounded knowledge outperformed the systems built around it, at lower cost. Once the agent no longer needs a persistent identity, the design problem shifts: from sculpting a more capable individual worker to structuring, reconciling, and synthesizing the collective intelligence that transient workers generate.

This shift from agent-centric optimization to knowledge-centric curation fundamentally changes how AI systems accumulate progress. Because a knowledge base lives outside any single model’s weights or runner, it can be version-controlled, diffed, audited by human experts, and shared across different LLM families. As autonomous systems scale, the frontier isn’t building better-tuned, isolated agents—it is building a shared, inspectable substrate of reusable knowledge that makes every future agent smarter.
