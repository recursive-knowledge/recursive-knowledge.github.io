Why Method Results Knowledge Transfer Takeaway

Why not just fix the agent?

An agent fails a task, and there’s a whole ladder of ways to improve it. Tune its prompt (GEPA, OpenEvolve). Rewrite the harness around it (Meta-Harness). Let it distill its own successful runs into a skill library (Voyager, SkillWeaver). Let it edit its own source (DGM). Breed a population and keep the winners (HyperAgents).

Every rung makes the same bet: the agent is what should carry the improvement. That bet gets expensive. One persistent agent has to absorb every lesson it ever learns, and those lessons are often task-specific, redundant, or flatly contradictory. Useful behavior gets diluted by conflicting updates, and each new adaptation risks breaking what already worked.

So invert the setup. Keep the agent generic, stateless, and disposable, and let improvement accumulate in what the agents write down. No single agent decides what’s true: claims compete in a task-level forum, get tested for recurrence across tasks, and only survivors are distilled. The solver is identical at generation 1 and generation 10. Only the notes grow.

Prior work is grouped by what it leaves behind and how experience turns into that artifact. The last column is the variable we hold fixed: in our setup the solver never changes, so any improvement has to come from the knowledge base.

Holding the solver fixed turns a design preference into a measurement. If a stock agent with good notes beats a purpose-built self-improving system, then what was scarce was never agent machinery. It was what the agent knew walking in.

The bottleneck may not be the complexity of the agent architecture, but the quality and structure of the information it can access and refine over time.

That is the claim this work is really making, and the rest of the page is an attempt to test it.

The agents run a message board

The mechanism is less exotic than “knowledge curation” sounds. It is a discussion board. Each task has its own thread. A second thread spans every task in the generation. Agents post what they found, quote earlier posts by id, and reply to each other agreeing, disagreeing, or refining. A distillation pass at the end decides what is worth handing to the next generation.

Every agent is a fresh, stateless solver: it seeds from the shared knowledge base, attempts one task, and writes evidence back. Solved tasks leave the pool, so each generation spends its budget only on what is still open.

Stage 1

Task-level forum

Agents turn raw traces into local evidence — what helped, what misled — scoped to the task it came from.

Stage 2

Cross-task forum

Agents discuss what transfers across the generation’s tasks. Each claim is grounded in a primitive; replies agree, disagree, refine, or synthesize — disagreement counts as evidence, not noise.

Stage 3

Distillation

Surviving claims are distilled into typed bundles and written back to the base; the next generation seeds from them.

Disagreement is the signal, not the noise

The obvious failure mode for a shared notes file is that it fills with confident, useless advice. The forum is built to prevent that, and the mechanism is disagreement. When two agents come back with conflicting accounts, the cross-task stage does not average them or take the more confident one. It keeps both and asks what distinguishes them — which is how a claim acquires the conditions under which it holds.

Here is one thread from the Terminal-Bench 2 run, traced through the shipped knowledge base. In generation 1, two agents on two different HTML-filtering tasks both concluded that stripping scripts with a regex was fine. The forum recorded why it was not:

“regex-based script removal fails on nested quotes and CDATA; DOM traversal with selective node deletion preserves structure and handles edge cases like src attributes containing ‘script’ substrings”

post 253 · break-filter-js-from-html

That became a rejected hypothesis with an explicit boundary — it applies to HTML sanitization via regex filtering, and does not apply where DOM traversal with node deletion is required. The scoping is the point: the claim is not “never use regex.”

The same underlying belief kept resurfacing on unrelated tasks. By generation 8 the cross-task forum had evidence from three of them at once — regex-chess, large-scale-text-editing, sanitize-git-repo — and rejected the general form outright. By generation 9 it had sharpened to the actual mechanism: re.sub() without count=1 applies across the whole string, so later patterns corrupt lines written by earlier ones.

break-filter-js-from-html was first solved in generation 9, carrying notes that by then named the exact filter behavior it had to defeat. regex-chess was never solved at all — ten generations, reward 0.0 throughout. The forum diagnosed that failure precisely and still could not crack it, which is worth stating plainly: curated knowledge sharpens what the next agent knows, and that is not the same as making every task solvable.

Swap the backbone and it gets cheaper

The protocol is not tuned to one model family. Running the identical procedure on GPT-5.4-mini beats the Haiku 4.5 runs on every benchmark, and does it for less — ARC-AGI-1 lands at 93.3% for $16, against $234 for the strongest agent-centric baseline.

Does the knowledge transfer?

If the artifact only works on the tasks that produced it, it isn’t knowledge so much as a record. So we freeze a generation-10 bundle and apply it zero-shot to a disjoint set of tasks — no new forum discussion, no recipient-side distillation, nothing but the notes. The held-out tasks are ones both recipient models fail on their own, so the bar is deliberately unkind.

What this means

The setup was built to answer one question. Hold the agent fixed — stock model, no memory, no role, no custom orchestration — let only the notes change, and see whether that is enough to beat systems whose entire purpose is making the agent better. It was, on every benchmark we ran, usually for less money.

The uncomfortable reading is that a lot of agent engineering may be substituting for something cheaper. Not that scaffolds and harnesses are worthless, but that when a stock agent with good notes outperforms a purpose-built self-improving system, the binding constraint was information, not architecture. The regex-chess thread cuts the other way and is worth keeping in view: ten generations of correct, sharpening diagnosis never produced a solve. Better notes are not a universal solvent.

What makes the knowledge-centric framing interesting beyond the scores is what you are left holding. A tuned agent is a configuration. A knowledge base is a document — you can read it, argue with it, diff two versions, hand it to a different model family, or fold in what a human expert knows. None of those are available for a set of weights or a searched scaffold. If improvement lives in text, it can be pooled.

Everything here is reproducible with the open-source KSI framework, and the knowledge bases the runs produced are browsable above — including the threads where the agents got it wrong.
